# 要件定義書 — ミエル（mieru）

**人工衛星・肉眼観測支援 PWA**

| 項目 | 内容 |
|---|---|
| ドキュメント版 | v1.0 |
| 作成日 | 2026-09-18 |
| プロダクト名 | ミエル（`mieru`） |
| 一言で | 「今夜、衛星は見えるか」に**一言で答える**アプリ |

---

## 1. 背景と課題

ISS（国際宇宙ステーション）は条件が揃えば**金星より明るく**肉眼で見える。しかし実際に見るには
以下を全部満たす必要があり、既存サービスは「情報は出すが判断はユーザー任せ」になっている。

1. 衛星が自宅上空を通る（**軌道**）
2. その時刻に空が暗い（**薄明**）
3. しかし衛星自身は太陽に照らされている（**地球影に入っていない**）
4. 十分高い角度を通る（**最大仰角**）
5. **雲がない**
6. 起きていられる時間帯である（**生活時間**）

既存サービス（Heavens-Above 等）は 1・3・4 は正確だが英語で情報過多、そして**天気を見ていない**。
結果「予報を見て外に出たが曇っていた」が頻発する。

### 本プロダクトの立ち位置

> **情報ではなく「判断」を届ける。**
> 見えない日は何も届かない。見える日だけ、方角と時刻が届く。

## 2. コンセプト

| 原則 | 意味 |
|---|---|
| **通知は貴重品** | 条件が揃った日だけ通知する。オオカミ少年になった瞬間に価値がゼロになる |
| **答えを先に言う** | アプリを開いた0.5秒後に「今夜は見える／見えない」が分かる |
| **理由を添える** | 「見えない」と言うときは必ず理由（雲・低仰角・時間帯）を出す。納得感が継続利用を作る |
| **夜に見る前提** | 暗所で目が眩まないダークUI。屋外・片手・寒い指での操作を想定 |

## 3. ペルソナと利用シーン

### 主ユーザー：本人（高校教師・宮崎在住）
- 平日夜、自宅の庭やベランダから空を見る
- 授業や部活で生徒に「今夜ISS見えるよ」と共有したい
- スマホはホーム画面から即起動したい（＝PWA）

### 副ユーザー：家族・友人（数人〜数十人）
- 天文知識ゼロ。**「何時に、どっちの空を見ればいいか」だけ**分かればよい
- LINE公式アカウントを友だち追加するだけで通知が届いてほしい
- アプリのインストールはしたくない（LINEのリンクから開くだけ）

### 代表的なシーン

| 時刻 | 起きること |
|---|---|
| 朝 10:00 | 良いパスがある日だけ LINE で予告が届く（「今夜チャンスです」） |
| 夕 開始30分前 | リマインドが届く（「あと30分、南西の空です」） |
| 屋外 | LINEのリンクからPWAを開き、スカイマップで方角と経路を確認 |
| 平常時 | アプリを開くと「今夜は見られません（雲量92%）」＋今後7日の見通し |

## 4. スコープ

### フェーズ定義

| Phase | 内容 | 完了条件 |
|---|---|---|
| **P0 コア** | 軌道計算・可視判定・スコアリングのライブラリ | 既知のISSパスと誤差±30秒以内で一致 |

| **P4 発展** | Starlinkトレイン検出・共有画像生成 | — |

**本ドキュメントは P0〜P3 を対象とする。**

## 7. 対象衛星と、現実的な期待値

> **重要：** ここを曖昧にすると「通知が来たのに見えない」を量産する。正直に定義する。

### 7.1 ISS（国際宇宙ステーション）— 主役

| 項目 | 値 |
|---|---|
| 高度 | 約 400 km |
| 軌道傾斜角 | 51.6°（＝日本全土が可視範囲） |
| 周期 | 約 92.9 分 |
| 最大光度 | **約 −3.5 等**（金星級。市街地でも見える） |
| 見える頻度 | 可視期間が**約2ヶ月ごとに1〜2週間**まとまって来る。その間は朝夕に毎日1〜数回 |

**結論：本アプリの主対象。通知の価値が最も高い。**

### 7.2 Starlink — 期待値を正しく設定する必要がある

Starlinkは誤解が多い。正直に3つに分けて扱う。

| 種別 | 状態 | 光度 | 肉眼可視性 | 本アプリの扱い |
|---|---|---|---|---|
| **運用中の衛星（大多数）** | 高度約550km、遮光対策済み | 5〜7等 | **ほぼ見えない**（暗い空で目を凝らして点） | 通知しない。地図表示のみ |
| **打ち上げ直後のトレイン** | 高度約280〜350km、数十機が数珠つなぎ | 1〜4等 | **明確に見える。しかも壮観** | **これを検出して通知する** |
| **軌道上昇中の個別機** | 高度350〜550km、間隔が開いた状態 | 4〜6等 | 条件が良ければ辛うじて | 通知しない |

**「Starlinkトレイン」は打ち上げ後 数日〜約2週間**しか見られない。つまり Starlink 機能の本質は
**「打ち上げ検出」＋「トレイン期のみ通知」**である。全衛星を等しく扱う実装は無意味。

#### トレイン判定条件（P4で実装）

- 同一の国際識別符号（打ち上げID、例 `2026-123`）を共有する衛星が **20機以上**
- 平均高度が **400 km 未満**
- 平均近点離角の標準偏差が小さい（＝密集している）

### 7.3 その他

| 衛星 | 扱い |
|---|---|
| 中国宇宙ステーション（天宮/CSS） | 最大 −1〜−2等。**P4で追加候補**（ISSに次ぐ明るさ） |
| イリジウムフレア | **対象外**（旧世代機は退役済みでフレアは発生しない） |
| その他の明るい衛星 | 対象外 |

## 8. 外部サービス・データソース

| 用途 | サービス | 料金 | 制約・注意 |
|---|---|---|---|
| 軌道要素(TLE/GP) | **CelesTrak** | 無料 | 同一データを2時間に1回以上取得しないこと。ブラウザから直接叩かず自前でミラーする |
| 天気（雲量） | **Open-Meteo** | 無料・APIキー不要 | 非商用 10,000リクエスト/日。CORS対応済みでブラウザから直接可 |
| 通知 | **LINE Messaging API** | フリープラン | **無料メッセージ 200通/月**。push/broadcast は**配信人数分**カウント。reply（応答）は**カウント対象外** |
| PWA配信 | **Cloudflare Pages** | 無料 | 帯域無制限、独自ドメイン可、プライベートリポジトリ可 |
| 定時トリガ／Webhook | **Cloudflare Workers** | 無料 | **CPU 10ms/実行**（Cron含む）。重い計算は不可。Cron Trigger はアカウント5個まで |
| 重い定期計算 | **GitHub Actions** | 無料 | パブリックリポジトリは実行時間無制限。cron は最大15分程度の遅延あり |

> **LINE Notify は 2025年3月31日でサービス終了済み。** 本プロダクトは Messaging API を使用する。

### 8.1 LINE 無料枠の試算

```
無料枠 200通/月
├ 友だち 10人 の場合 → 20回/月 通知できる
├ 友だち 20人 の場合 → 10回/月 通知できる  ← 現実的な上限
└ 友だち 40人 の場合 →  5回/月 通知できる  ← 要有料プラン検討
```

ISSの可視期間は約2ヶ月ごとに集中するため、**通知は月あたり 0回 または 6〜12回**と偏る。
FR-6.6（残数チェック）と、予告＋リマインドで**1パス=2通**消費する点を設計に織り込む。

## 10. やらないこと（Out of Scope）

- 望遠鏡制御・追尾機能
- 衛星の3Dリアルタイム表示（地球儀グローブ）
- ISS以外の暗い衛星の個別通知
- ユーザー登録／パスワード認証（LINEの友だち関係を認証の代わりとする）
- 天体（惑星・流星群・彗星）の予報 ※将来の拡張余地としては残す
- Android/iOS ネイティブアプリの提供

## 11. リスクと対策

| # | リスク | 影響 | 対策 |
|---|---|---|---|
| R-1 | **通知が来たのに曇って見えない** → 信頼喪失 | 致命的 | 雲量をスコアの乗算因子にし、天気取得失敗時は**送らない**（FR-3.3）。開始30分前リマインド時に**雲量を再判定**して中止できるようにする |
| R-2 | GitHub Actions の scheduled workflow が60日無活動で自動停止 | 大 | Workerがデータ鮮度を監視し36時間以上古ければ管理者に警告（FR-7.1）。データ更新コミット自体が活動となる設計 |
| R-3 | LINE無料枠200通の超過 | 中 | 送信前残数チェックで停止（FR-6.6）。しきい値を上げて通知を絞る運用でも回避可能 |
| R-4 | CelesTrakのレート制限・仕様変更 | 中 | 1日1回のみ取得し自前ミラーに保存。取得失敗時は前回TLEで継続（元期7日以内なら実用精度） |
| R-5 | Starlinkへの過剰な期待 | 中 | 要件7.2の通り**トレイン期のみ**を通知対象とし、UI上でも明記する |
| R-6 | Cloudflare Worker 10ms CPU制限の超過 | 中 | Workerでは軌道計算をしない。事前計算済みJSONの読み出しと比較のみに限定する |
| R-7 | 夏場は日本の緯度でISSが一晩中日照 → パスが増えすぎる | 小 | スコアリングと上位N件表示で自然に吸収される |

## 12. 成功基準

| 観点 | 基準 |
|---|---|
| **精度** | Heavens-Above の同条件パス予報と、開始時刻±30秒／最大仰角±2°／方位角±3° 以内で一致する |
| **通知の的中率** | 通知を送ったパスのうち、**実際に見えた割合が80%以上**（残り20%は局所的な雲を許容） |
| **静穏性** | 見えない日に通知が飛ばないこと（誤通知ゼロ） |
| **速度** | ホーム画面のアイコンをタップしてから結論が読めるまで **2秒以内** |
| **継続** | 本人が1可視期間（約2週間）を通して使い続け、家族が最低1回は実際に空を見上げる |
| **コスト** | 運用3ヶ月時点の請求額 **0円** |

## 13. 用語集

| 用語 | 意味 |
|---|---|
| **TLE / GP** | 人工衛星の軌道要素。2行（または3行）形式の数値データ。SGP4の入力 |
| **SGP4** | TLEから任意時刻の衛星位置を求める標準伝播モデル |
| **パス（pass）** | 衛星が地平線上に現れてから沈むまでの一連の通過 |
| **仰角（elevation）** | 地平線を0°、真上を90°とした高さの角度 |
| **方位角（azimuth）** | 北を0°として時計回りに測った方角（東=90°, 南=180°, 西=270°） |
| **最大仰角** | そのパスで最も高く昇ったときの仰角。観測しやすさの主要指標 |
| **薄明（twilight）** | 日没後・日の出前の空が完全には暗くない時間帯。太陽高度 −0°〜−18° |
| **市民薄明** | 太陽高度 −6° まで。まだ明るく、明るい星しか見えない |
| **天文薄明** | 太陽高度 −18° まで。これを過ぎると完全な夜 |
| **地球影（umbra/penumbra）** | 地球が作る影。衛星がここに入ると太陽光を反射せず見えなくなる |
| **等級（magnitude）** | 天体の明るさ。**数値が小さいほど明るい**。0等＝ベガ、−1.5等＝シリウス、−4等＝金星 |
| **Starlinkトレイン** | 打ち上げ直後のStarlink衛星が数珠つなぎに並んで見える現象 |
